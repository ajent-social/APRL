# T6.2 — Persist delegation identity and lifecycle creation atomically

## Purpose

Add the durable caller/delegation binding required to make retries idempotent across process restart and concurrent requests. The database, not a process mutex or in-memory cache, is the authority.

## Dependencies

Begin after T6.1.R has independently approved and verified T6.1's exact landing.

## Ownership

Own a new `internal/plantasks/delegations.go`, the required migration, and focused real-PostgreSQL integration tests. Do not edit the generic claim/task tooling, the frozen protocol, shared plan, or provider/profile registration.

## Requirements

- Persist an immutable binding from authenticated `(caller_id, delegation_id)` to exact canonical request bytes and digest, all immutable external scope and policy inputs, the internal lifecycle UUID, exact expiry, and current external observation sequence/replay record.
- First persist the unique INTENT binding before evaluating admission policy. Its lifecycle_id is nullable for INTENT, temporary unavailability and terminal DENIED. Under the durable key lock, definitive denial transitions INTENT to DENIED without children; successful authorization atomically transitions INTENT to ADMITTED and creates its one lifecycle/tasks, making lifecycle_id nonnull. DENIED is terminal; temporary unavailability retains INTENT. Enforce database uniqueness and serialize concurrent decisions without evaluating external policy under the database lock.
- For ADMITTED, identical retries return the same lifecycle and exact persisted observation, including after reopening the store. DENIED replays the same redacted 403 with null lifecycle_id and no children. INTENT or temporary 503 reuses the durable key and can only pass through that single serialized admission decision; it does not promise a lifecycle. A changed request or digest for the same key conflicts and creates no second lifecycle.
- Persist caller `project_id`, `job_id`, `task_id`, `plan_revision`, and `plan_digest`; repository/target/source commit; acceptance; policy/profile revisions; execution mode; exact envelope; `max_concurrent`; and `max_attempts`. Never infer these from the internal lifecycle UUID or `State.Revision`.
- Keep the protocol's `max_attempts` as one conservative lifecycle-wide maximum across every agent admission, including review and bounded corrections; do not reset the limit for each child. Positive `1` is valid wire syntax. Host authorization must deny a limit that cannot include mandatory independent review.
- Preserve exact external expiry and check it before every admission and externally visible fact update. Duration rounding or conversion must never extend the caller's expiry.
- Make cancellation a durable monotonic fence. Replays do not reopen the lifecycle, erase accepted facts, or turn uncertain outcomes into settled results. Persist observations with a monotonic sequence so stale updates cannot roll back a newer result.
- Preserve the existing standalone lifecycle path through the same `plantasks.Adapter` and scheduler. Adding caller/delegation binding must not make the previously complete standalone author → review → correction/re-review → verified-landing flow unavailable or route it through a second scheduler.
- Keep accounting semantics conservative: v1 is subscription-only and zero-cost under an explicit qualified host policy. Do not create a settlement ID or infer known-zero usage from worker completion, cancellation, timeout, merge, or process reaping; ambiguous exposure remains unknown.

## Verification

Real-PostgreSQL tests must cover identical retry, changed-digest conflict, concurrent identical create (one lifecycle), reopen/replay, exact stored request/scope/expiry, stale sequence rejection, cancellation monotonicity, and unchanged task counts after each denied operation. Also exercise the pre-existing standalone author → independent review → negative review → bounded correction/re-review → verified landing flow through the unchanged adapter path after adding the delegation binding. Include a genuine-red test that disables the database uniqueness/transaction predicate and demonstrates duplicate lifecycle creation or a failed assertion; restore the predicate and rerun. Record actual terminal test counts, failures, and skips.

## Delivery

Commit only the owned store, migration, and integration-test paths. Hand off the exact PR URL/head/base for independent T6.2.R review. T6.3 and later consumers wait for verified review and landing.

## Boundaries

This task proves durable storage behavior against PostgreSQL fixtures only. It does not authorize callers, expose HTTP routes, establish cross-repository interoperability, or qualify paid/provider/runtime behavior.

Pre-work denial binding: after authentication and strict codec validation, reserve caller/delegation/digest intent; definitive policy denial persists no lifecycle/children and cannot later create them under that key. Same input replays the redacted 403 denial, changed input conflicts 409; temporary policy unavailability 503 retains intent for same-digest reconciliation without execution. Unauthenticated/malformed input binds no key. Test both terminal denial and temporary unavailability in real PostgreSQL.
