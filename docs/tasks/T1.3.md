## T1.3: Freeze versioned job, event, result and review contracts

### Objective
Version 1 carries task/job/generation, lease token, snapshot, attempt, operation ID and correlation; malformed payloads, inconsistent verdicts, and incomplete anchors reject; unanchored blockers validate.

### Scope
- `internal/contracts/types.go`
- `schemas/job-v1.json`
- `schemas/result-v1.json`
- `schemas/review-v1.json`
- `tests/unit/contracts_test.go`
- `docs/contracts.md`

### Out of scope
Other task-owned modules, live GitHub mutations, paid model calls, production deployment, and changes to the RFC's guarantees. Coordinate contract amendments through the coordinator instead of expanding file ownership.

### Dependencies
T1.1; see `docs/plan.md`. Interfaces are frozen by T1.3; consumer packages define their own narrow interfaces when implemented. Shared versioned data belongs in internal/contracts, not provider-side god interfaces. Imported dependencies can be consumed but their files are not owned by this task.

### Acceptance criteria
- Budget/envelope contracts use integer micro-USD, bounded integer token counts, and explicit pricing identity. No float64 money or downward rounding.
- Version 1 carries task/job/generation, lease token, snapshot, attempt, operation ID and correlation; malformed payloads, inconsistent verdicts, and incomplete anchors reject; unanchored blockers validate.
- For behavior changes, perform a genuine-red check: Remove a required generation field from a fixture and observe validation failure. Restore the behavior and record failing and passing verification outputs. Any intentional breakage belongs only in the task's owned isolated worktree.
- Tests must exercise the real boundary stated above; database/Redis integration fixtures fail if required services are missing, rather than skip.
- Keep new API status/body shapes consistent with `docs/contracts.md` and tested through real HTTP requests when applicable.
