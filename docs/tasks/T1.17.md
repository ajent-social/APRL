## T1.17: Assemble separately supervised service roles and health APIs

### Objective
Commands api/control/worker start separate roles with shared contracts. GET /healthz returns 200 status alive; GET /readyz returns 200 status ready only with DB/role dependencies available, otherwise 503 status not_ready with dependency names and no secrets. Control loops use bounded polling, persisted deadlines, signal-driven shutdown and no queue-held locks while waiting on CI.

### Scope
- `internal/app/app.go`
- `cmd/aprl/main.go`
- `tests/api/health_test.go`
- `tests/integration/service_roles_test.go`

### Out of scope
Other task-owned modules, live GitHub mutations, paid model calls, production deployment, and changes to the RFC's guarantees. Coordinate contract amendments through the coordinator instead of expanding file ownership.

### Dependencies

### Acceptance criteria
- Production paths contain no default test doubles or hardcoded success.
- API/control roles can run in the foundation; production worker startup fails closed until E2 supplies the real OCI/provider adapters. Tests may inject fixture adapters but deployment flags cannot enable them.
- Commands api/control/worker start separate roles with shared contracts. GET /healthz returns 200 status alive; GET /readyz returns 200 status ready only with DB/role dependencies available, otherwise 503 status not_ready with dependency names and no secrets. Control loops use bounded polling, persisted deadlines, signal-driven shutdown and no queue-held locks while waiting on CI.
- For behavior changes, perform a genuine-red check: Stop a required backing service and assert readiness 503 while liveness remains 200. Restore the behavior and record failing and passing verification outputs. Any intentional breakage belongs only in the task's owned isolated worktree.
- Tests must exercise the real boundary stated above; database/Redis integration fixtures fail if required services are missing, rather than skip.
- Keep new API status/body shapes consistent with `docs/contracts.md` and tested through real HTTP requests when applicable.
