### Assembly boundary (coordinator clarification)

The control role runs durable inbox, dispatcher, reconciliation, and exact-run cancellation loops; inference execution belongs only to the worker role. Mandatory startup inventory/recovery must finish before any expiry, dispatch, claim or other mutation. Missing trusted inventory evidence leaves unresolved holds charged and readiness unavailable.

Trusted supervisor authentication derives the principal outside request JSON. Assembly takes explicit trusted authentication, inventory, host process, cancellation, broker and label adapters. Typed-nil dependencies are unavailable. The command must not synthesize a host principal, process recovery proof, numeric-PID cancellation capability or successful provider adapter. Missing production adapters produce stable dependency names and fail closed; test injection supplies fixtures without adding a deployment flag that enables them.

Readiness probes are bounded and role-specific, with deterministic sorted dependency names and no URLs, credentials or raw errors in responses. Liveness remains independent of backing service readiness. Shutdown cancels and joins role loops within a configured bound; caller-owned DB/Redis clients remain open. Cancellation requests only a bounded acknowledgement and must not wait for termination, reaping, provider work or CI. Existing dispatcher acknowledgement may hold only its outbox row; task/org locks never span external calls, and no queue-held lock spans a CI wait. Foundation tests prove assembled trusted seams; their evidence does not qualify production OCI/provider operation or external code-delivery/v1 interoperability.

A separate test author owns only `tests/api/health_test.go` and `tests/integration/service_roles_test.go` under the `R-t1-17-tests` file-ownership resource. Each uses its own external worktree. The exported surface is frozen as follows; package names refer to the existing concrete contracts. Changes require coordinator reconciliation before either lane changes its assumptions.

```go
type Role string // constants RoleAPI, RoleControl, RoleWorker

type Config struct {
    Role Role
    ListenAddr string
    StartupTimeout, RecoveryTimeout, RPCDeadline time.Duration
    PollInterval, ShutdownTimeout, ReadinessTimeout time.Duration
    ReadinessPollInterval time.Duration
    MaxRequestBodyBytes int64
    DispatchBatch int
    ConsumerName string
}
type StartupRecovery interface {
    Recover(context.Context) error
    Ready(context.Context) error
}
type ReadinessProbe interface { Check(context.Context) error }
type DependencyStatus struct {
    Name string `json:"name"`
    Ready bool `json:"ready"`
    Code string `json:"code,omitempty"`
}
type Readiness struct {
    Role Role `json:"role"`
    Ready bool `json:"ready"`
    Dependencies []DependencyStatus `json:"dependencies"`
}
type APIDependencies struct {
    Pool *pgxpool.Pool
    Clock clock.Clock
    RouterConfig router.Config
    WebhookSecret []byte
    SupervisorAuth httpapi.SupervisorAuthenticator
    StartupRecovery StartupRecovery
}
type ControlDependencies struct {
    Pool *pgxpool.Pool
    Redis *redis.Client
    Clock clock.Clock
    Streams *queue.Streams
    RouterConfig router.Config
    Operations reconcile.OperationReconciler
    Labels reconcile.LabelOutputter
    ReconcileConfig reconcile.Config
    CancelAck, NotifyAck dispatch.Handler
    StartupRecovery StartupRecovery
}
type WorkerDependencies struct {
    Pool *pgxpool.Pool
    Redis *redis.Client
    Clock clock.Clock
    Streams *queue.Streams
    Runner supervisor.Runner
    ResultSubmitter supervisor.ResultSubmitter
    Holds *processholds.Store
    SupervisorConfig supervisor.Config
    ConsumerConfig queue.ConsumerConfig
    BudgetEnvelope contracts.BudgetEnvelope
    StartupRecovery StartupRecovery
    OCIReadiness, ProviderReadiness, HostReadiness ReadinessProbe
}
func NewAPI(Config, APIDependencies) (*App, error)
func NewControl(Config, ControlDependencies) (*App, error)
func NewWorker(Config, WorkerDependencies) (*App, error)
func (*App) Handler() http.Handler
func (*App) Ready(context.Context) Readiness
func (*App) Run(context.Context) error
func (*App) Shutdown(context.Context) error
```

NewAPI assembles the real router/results/webhook/result handlers; API ingress and result acceptance mutate durable state but never run control or inference loops. NewControl assembles real inbox polling, dispatcher and reconciliation; Streams is the publisher, inventory readiness derives from StartupRecovery.Ready, and the fence is leases.FenceExpiredTask. CancelAck is wrapped with strict task/job/run payload validation, rejects missing run_id and mismatched outbox bindings, permits an explicit empty run_id without physical cancellation, and never retargets a replacement. NewWorker assembles supervisor and consumer using the same explicit immutable BudgetEnvelope for concrete budget.Reserve admission and Supervisor.Run execution.

The startup-complete flag remains false until bounded Recover succeeds; current Ready is checked afterwards. Redis readiness uses bounded Ping, not a mutating EnsureGroup. EnsureGroup and all work loops start only after recovery. Health routes exist for all roles; business routes exist only for API. Ready HTTP responses expose the documented status ready/not_ready plus fixed sorted safe dependency names; health status remains alive. Caller-owned DB/Redis stay open after App shutdown. Configuration and adapter calls are finite; missing trusted production factories fail closed and no CLI option enables fixtures.

Public health serialization preserves `docs/contracts.md`: `/readyz` success returns `{"status":"ready"}`; failure returns `{"status":"not_ready","dependencies":["postgres"]}` with only sorted unavailable safe dependency names. The exported `App.Ready` structs are internal host API results, not a replacement HTTP wire schema.

Inventory availability is current admission authority, not a one-time startup flag. After recovery succeeds, a later `StartupRecovery.Ready` failure prevents new API business mutations, control inbox/dispatch work and worker claims; health remains live and readiness reports unavailable. Existing effects are reconciled through their trusted bounded paths rather than granting new work from stale startup success.

Startup is bounded and fail closed: initial recovery failure or startup readiness timeout returns a `Run` error, stops the owned health listener and starts no business loop. A host supervisor must restart a failed role; assembly does not add a retry scheduler. Once a role has successfully started, backing dependency loss makes readiness unavailable while liveness stays alive until explicit shutdown. Constructor/handler tests and the owned-service outage probe distinguish these cases.

Removing only the PostgreSQL readiness predicate genuinely failed the outage assertion; exact restoration passed. The private probe uses explicit test-only authentication/recovery seams and proves no production trust or provider capability. Its harness waits for actual database startup readiness; an initial probe restart timing failure was retained and corrected rather than attributed to production behavior.

Role admission checks current bounded dependency readiness before API mutations, each routed/dispatch item, each worker claim and budget reservation. Runtime role-loop failure reports a safe fixed `control_loop` or `worker_loop` dependency and retries after polling/current prerequisites; that loop-status bit is excluded only from its own restart prerequisites. Initial startup failure remains bounded and requires a host supervisor restart.
