# T6.3 — Serve caller-scoped HTTPS lifecycle endpoints

## Purpose

Expose the frozen v1 lifecycle API over a bounded, authenticated HTTP boundary backed by the T6.2 durable store. The handler invokes APRL's existing lifecycle adapter; it must not create a second scheduler or an alternate readiness path.

## Dependencies

Begin after T6.2.R has independently approved and verified T6.2's exact landing.

## Ownership

Own a new `internal/plantasks/http.go` and focused API tests. Use injected trusted authentication and host authorization interfaces. Do not change the frozen wire schema, generic task tooling, plan, runbook, or deployment configuration.

## Requirements

- Implement exactly the frozen `PUT /v1/delegations/{delegation_id}`, `GET /v1/delegations/{delegation_id}`, and `POST /v1/delegations/{delegation_id}/cancel` routes and response shapes.
- Authenticate the caller from a trusted HTTPS bearer authenticator. Ignore caller identity in request JSON for authentication; bind the authenticated principal to the request `caller_id` and path delegation ID. Caller-scoped GET/cancel must not disclose whether another caller's delegation exists.
- Invoke a host-controlled authorizer for caller/project/repository/policy scope and subscription-only zero-cost eligibility. The host must deny a global attempt bound that cannot accommodate mandatory independent review. No repository-controlled input may select an executable, credential, provider, profile, or authorization policy.
- Require production HTTPS. Any loopback HTTP exception is an explicit test-only transport mode and cannot be enabled by production defaults.
- Bound request and response bodies to 1 MiB; require the frozen content type and supported methods; reject duplicate/unknown members, trailing JSON, malformed/path-mismatched bindings, unsupported versions, and unsafe redirects carrying credentials. Apply finite request contexts and return stable redacted errors without tokens, raw infrastructure errors, or cross-caller data.
- Preserve exact external expiry and reject expired requests before creating or changing lifecycle facts. Retries go through the T6.2 idempotent transaction.

## Verification

API tests must use real PostgreSQL storage with injected test-only authentication and policy adapters. Cover successful PUT/GET, duplicate identical PUT, changed request conflict, wrong principal and delegation path, other-caller read/cancel denial without existence leaks, malformed/oversized/unknown/duplicate/trailing JSON, unsupported content type/method, expired request, insufficient mandatory-review capacity, redacted errors, and test-only loopback gating. Include a genuine-red check proving the caller-binding guard rejects a mismatched identity, restore it, and rerun. Record positive terminal test counts and zero skips/failures.

## Delivery

Commit only the HTTP implementation and its API tests. Hand off the PR URL and exact head/base for independent T6.3.R review. No production endpoint/profile is installed by this task.

## Boundaries

Passing handler tests establish behavior only with test-authenticator and authorizer adapters. They do not prove external TLS deployment, real identity-provider configuration, service-to-service interoperability, paid execution, or runtime activation.

Frozen response compatibility: only authorized canonical lifecycle creation/projection returns 200/201/202 Observation. Policy denial 403, changed digest 409 and temporary policy unavailability 503 are redacted JSON errors, consistent with the existing non-success boundary. GET/replay for a caller-scoped denied intent returns the stable denial without a fabricated lifecycle or new wire field. Test unauthenticated/malformed no-binding and no other-caller existence leak.
