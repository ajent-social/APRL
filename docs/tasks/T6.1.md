# T6.1 — Implement the `code-delivery/v1` codec

## Purpose

Implement the neutral wire representation already frozen in [`code-delivery/v1`](../contracts/code-delivery-v1.md). This task defines no new fields or protocol version and does not implement the service adapter.

## Dependencies

Begin only after T6.0 and its independent review T6.0.R have landed. The exact caller-side canonical request and digest fixtures are authoritative inputs.

## Ownership

Own `internal/plantasks/deliveryv1.go`, focused codec tests, and synthetic golden fixtures under `docs/contracts/fixtures/`. Do not edit the frozen contract, plan, runbook, generic task tooling, or runtime configuration.

## Requirements

- Implement the v1 request and observation types with the frozen ordered UTF-8 JSON encoding and SHA-256 digest. Match the caller's golden bytes and digest exactly, including escaping and absence of a trailing newline.
- Strictly validate the entire bounded document: at most 1 MiB; one JSON value; no duplicate or unknown members; no trailing data; required fields, supported version/enums, bounded positive attempt/concurrency values, valid dependencies, and no duplicate task identities.
- Treat caller project/job/task/delegation identifiers as opaque protocol strings within documented bounds. Do not require UUIDs or map them directly to APRL claims. APRL claim identities remain the canonical internal `T-<UUID>` identifiers.
- Accept `max_attempts=1` as structurally valid. Do not reinterpret it as a per-child limit; host policy must reject any request whose one global admission limit cannot accommodate mandatory independent review.
- Preserve exact `expires_at` for enforcement. A rounded internal duration may not extend external validity.
- Represent the frozen task stages/enums exactly, including wire `re_review`. Do not add an executable synthetic delivery child; use T6.0's approved mapping for the existing stable review gate.
- Keep monetary fields and subscription-only mode exactly as specified by v1. The codec must not infer settlement, spend, or known-zero use from completion or process state.

## Verification

Add pure tests for golden request bytes/digest, accepted minimum limits, boundary sizes, invalid UTF-8/JSON, duplicate and unknown members at nested levels, trailing values, missing fields, invalid enums/IDs, graph errors, exact expiry serialization, and observation canonicalization. Tests must assert the precise error class or validation result, not merely that parsing failed.

Run the focused package selector and report actual terminal test counts, failures, and skips. Add a genuine-red check showing that a changed key order or digest fails the frozen golden assertion, restore the fixture, and record the passing rerun. No live services are required for this task.

## Delivery

Commit only the owned paths. Hand off the PR URL and exact head/base for the normal independent T6.1.R review; implementation is not complete until that review approves and verifies landing.

## Boundaries

This is codec evidence only. It does not prove authenticated HTTP interoperability, durable idempotency, lifecycle projection, external caller compatibility beyond the frozen fixtures, production authorization, paid execution, or runtime activation.

Unicode decoder decision (2026-10-03, coordinator): reject raw JSON unpaired UTF-16 surrogate escapes as ErrDeliveryV1Malformed, accepting valid high/low pairs and literal valid U+FFFD. The standard Go decoder silently replaces unpaired escapes; this strict boundary avoids lossy normalization. A valid UTF-8 caller value serialized by its canonical encoder cannot produce an unpaired surrogate, so canonical producer compatibility is preserved. This is codec validation only and changes no wire fields or admission authority. Independent tests and exact-head review must verify it.
